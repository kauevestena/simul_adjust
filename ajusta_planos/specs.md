- Use similar colors and layout to other LSQ simulators like "nivelamento" and "estacao_livre"
- One fundamental user input is the nominal 1 sigma precision of the observations, default values must be 2 mm + 2 ppm for the EDM and 2 arcsec for the angles. The user can change these values in the "Settings" tab.
- The "modelo combinado" type of adjustment shall be used, please refer to the GEMAEL-related literature, we are going to be fitting planes using the computed XYZ coordinates of the observations, and the MVC - covariance matrix (1 sigma) of the XYZ coordinates. Remember, plane equation: 
    - Ax + By + Cz + D = 0
    - so the unknowns are A, B, C and D. Classic "Metodo Combinado" must be followed, having the 4 unknowns to be estimated, free of any constraint. Optionally the user can opt for normalizing the parameters after computation (by clicking a button), so that A^2 + B^2 + C^2 = 1, which is the most common way of representing a plane. The vector sense will also be normalized in that case, so the rule to choose between the two possible cases is the following: for "vertical" planes the one nearer to Z axis will be chosen, for "horizontal" planes the one nearer to X axis will be chosen. To define if a plane is more "horizontal" or "vertical", inner displacement vectors shall be computed, so if there are small Z variability therefore is a vertical plane, otherwise is a horizontal plane. If the user opt for the normalization, the MVC of the 4 parameters must be computed using the Jacobian matrix of the normalization transformation, so that the covariance of the normalized parameters is available for further analysis.
- There are sample observations available for testing, please refer to the "ajusta_planos/about_samples.md" file for more information. The web app shall be able to read the CSV files and process them, so that the user can test the app with the sample observations. The user can also provide his own observations in CSV format, following the same structure of the sample observations.
- There is a sample implementation of the "AJustamento combinado", even tought is for 2D planimetric networks, not for plane fitting ( ajusta_planos/sample_implementations/2d_positional_network.cpp ). Another sample implementation and this time actually holding plane fitting using the combinado method is available at https://github.com/kauevestena/smmt/blob/master/or_relativ.hpp in the method leasqPlane2(tell me if you want me to copy it to the "ajusta_planos/sample_implementations" folder).
- The main canvas shall be a 3D viewer, showing the original XYZ points, optionally showing their error ellipsoids (which scale can be changed by the user). After the adjustment, the fitted plane shall be shown, deactivating the ellipsoids by default (the user can reactivate them) and showing the residuals of the points to the fitted plane. The user can rotate, zoom and pan the 3D view, and also change the colors of the points, ellipsoids and plane.
- A parallel 2D view shall be available, showing a digital model of the residuals of the points to the fitted plane, with a color scale representing the magnitude of the residuals. The user can change the color scale and the range of the residuals to be shown. The user can also choose to show the residuals in absolute values or in signed values (positive or negative). 3 methods shall be available to show: TIN, IDW and Kriging. The user can also choose to show the residuals as a heatmap or as contour lines.
- All of the matrices of the Adjustment shall be available for the user to see, including the Jacobian matrix of the transformation from GMS to XYZ coordinates, the covariance matrix of the observations, the covariance matrix of the XYZ coordinates, the normal equations matrix, the covariance matrix of the unknowns and the residuals vector. The user can also choose to export these matrices to CSV files.
- As in the other simulations, outlier detection algorithms shall be available. First of all the global test shall be shown. Then the user can opt by one of 3 methods: 3 sigma rule; iterative data-snooping; or using RANSAC. 
- Outlier detection shall happen after the adjustment, so the user can have it to deactivate in the table view the outliers, and then re-run the adjustment without the outliers.
- optional normalization is only after the outlier detection, so the user can choose to normalize the parameters after the outliers have been optionally removed.  So the workflow is : 1) adjustment; 2) outlier detection; 3) optional removal of outliers; 4) re-run adjustment without outliers (as many times as needed); 5) optional normalization of the parameters; 6) export of the results and matrices, mainly the 4 parameters and their covariance matrix, which can be used for further analysis.
